3. Behavioral Questions (STAR Method)

Q: Tell me about a challenging project you worked on.

Situation: At Reliance Cloud, I was assigned to lead an AWS cloud migration project for a client with legacy on-premise systems.

Task: I needed to migrate their applications to AWS while ensuring zero downtime and maintaining data integrity.

Action: I designed a phased migration strategy using AWS CloudFormation for infrastructure as code. I set up parallel environments, implemented proper VPC networking with security groups, and created automated testing pipelines. I also conducted daily standups to keep stakeholders informed.

Result: We completed the migration successfully with zero downtime. The client saw a 40% reduction in infrastructure costs and improved application performance. This project helped me earn recognition and additional AWS certifications.

Q: Describe a time you had to learn something quickly.

Situation: When I joined IDOL Consulting, I needed to quickly learn Flutter and mPaas for the Telkom Super App project, technologies I hadn't used before.

Task: I had to become productive within the first two weeks to contribute to the sprint deliverables.

Action: I dedicated evenings and weekends to intensive learning. I built a personal project (ProjectHub - a task management app) using React Native to understand cross-platform mobile development patterns. I studied the existing codebase, asked questions in code reviews, and paired with senior developers.

Result: Within two weeks, I was contributing production code. Within a month, I was independently building features and helping troubleshoot performance bottlenecks across platforms.

Q: Tell me about a time you disagreed with a team member.

Situation: At Exonic Solutions, a colleague wanted to use a monolithic architecture for a new project, while I believed a serverless microservices approach would be better.

Task: I needed to present my case while maintaining a good working relationship.

Action: Instead of arguing, I prepared a comparison document showing the pros and cons of both approaches, including cost projections, scalability considerations, and maintenance overhead. I presented this in a team meeting, acknowledging the valid points of the monolithic approach.

Result: The team decided to go with the serverless approach after seeing the data. More importantly, my colleague appreciated the respectful way I handled the disagreement, and we collaborated effectively throughout the project.

Q: Describe a time you failed and what you learned.

Situation: Early in my career at Reliance Cloud, I pushed code to production without adequate testing, which caused a brief service disruption.

Task: I needed to fix the issue immediately and ensure it never happened again.

Action: I quickly rolled back the changes and fixed the bug. Then I took ownership by presenting a post-mortem to the team. I proposed implementing a CI/CD pipeline with automated testing gates, which I then helped build using AWS Amplify.

Result: We never had a similar incident again. The CI/CD pipeline I helped implement became a standard practice for all projects. I learned that thorough testing and proper deployment processes are non-negotiable, especially in production environments.

4. Technical Questions

Q: Explain your experience with AWS cloud services.

I have extensive hands-on experience with AWS, backed by my AWS Cloud Practitioner and Developer Associate certifications:

  • Compute: Lambda for serverless functions, EC2 for virtual servers
  • Infrastructure as Code: CloudFormation and CDK for defining and deploying infrastructure
  • Storage & Databases: S3, DynamoDB, RDS (PostgreSQL, MySQL)
  • Networking: VPC configuration, security groups, network ACLs
  • CI/CD: AWS Amplify for frontend deployments, CodePipeline
  • Security: IAM roles and policies, secrets management

At Reliance Cloud, I led cloud migration projects and built event-driven architectures using these services.

Q: How do you ensure code quality?
  • Code Reviews: I participate in peer reviews and provide constructive feedback
  • Testing: I write unit tests (e.g., my ProjectHub has 67 unit tests with Jest)
  • CI/CD: Automated pipelines that run tests before deployment
  • Best Practices: Following SOLID principles, clean code practices, and proper documentation
  • Version Control: Meaningful commits, feature branches, and proper Git workflows
Q: Explain REST API design principles.
  • Resource-based URLs: /api/users, /api/projects/:id
  • HTTP Methods: GET (read), POST (create), PUT (update), DELETE (remove)
  • Statelessness: Each request contains all information needed
  • Status Codes: 200 (success), 201 (created), 400 (bad request), 401 (unauthorized), 404 (not found), 500 (server error)
  • Security: JWT authentication, input validation, parameterized queries to prevent SQL injection

In my ProjectHub app, I implemented a full REST API with 14 endpoints following these principles.

Q: How do you handle security in applications?
  • Authentication: JWT tokens with secure storage (SecureStore in mobile apps)
  • Password Security: bcrypt hashing, never storing plain text passwords
  • Input Validation: Server-side validation, sanitizing user inputs
  • SQL Injection Prevention: Parameterized queries
  • HTTPS: Always use encrypted connections
  • CORS: Proper configuration for allowed origins
  • AWS Security: IAM least-privilege principle, security groups, VPC isolation

I've practiced Agile/Scrum throughout my career:
